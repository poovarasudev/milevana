## Notes

- Phase 1B removed `src/data/store.ts` entirely; all screens read repository
  snapshots via `useAppStore` and write through feature modules. Jest maps
  `data/firebase` to the neutral `firebase.ts` stub so tests inject a fake
  adapter (`src/features/__tests__/fakeAdapter.ts`); platform bundles resolve
  the real adapter via Metro's platform extensions.
- Two fixed bugs found by the new tests: `guardedWrite`/`confirmBatch` now
  clear their timeout when the write wins the race (previously a successful
  write still flipped the offline banner 15 s later), and the Connect retry
  timer is cancelled on session teardown.
- `tsconfig.json` gained `"types": ["jest", "node"]` — TypeScript 6 does not auto-include `@types` packages the way earlier versions did, so Jest globals were missing.
- Phase 3 (Reminders): `data/notifications` follows the same neutral/platform
  pattern as `data/firebase` — Jest maps to `notifications.ts`, Metro resolves
  `.native`/`.web`. Snooze is device-local (AsyncStorage `remSnoozes`), not
  synced; per RD-06.
- Phase 5 adds the Drive module under `src/data/drive/` (`client.ts` is the
  neutral contract — Jest maps `*/client` to it, Metro resolves
  `.native`/`.web`) plus `localFiles`/`receiptPick`/`shareOut`/`receiptView`
  with the same three-file pattern. `EntryPatch` gained `uploaderUids` so a
  queued upload can record who uploaded the file.
- Phase 8: the deletion engine lazy-loads `driveCleanup`/`reminders` after the
  account step so the node emulator suite can run it without React Native;
  `tests-stubs/async-storage.js` stands in for AsyncStorage there. `app.json`
  `extra.eas.projectId` is `OWNER-EAS-PROJECT-ID` until the owner creates the
  EAS project. The web `/delete-account` route never offers deletion to
  anonymous sessions (SC-REL08-03) and the `deleting` phase gates *every*
  route, so a cross-device resume cannot be bypassed by opening another page.
- Phase 7 note — rules vs item validation: wiring `templateItemOk` into
  `validTemplate` (all 50 slots) makes Firestore deny *legitimate* 50-item
  writes — `||` only absorbs the error's result, not its evaluation cost, so
  every slot always evaluates and the request exceeds the 1000-expression
  budget (emulator-verified). The rules therefore keep the documented
  contract (members only, `createdBy` checks, ≤50 items) and item shape is
  enforced by `templateRepo`'s zod schema on write plus skip-on-read.
  `RNTL` note: `fireEvent.*` is async in `@testing-library/react-native` 14 —
  every press/changeText in component tests must be awaited or the assertion
  races the state flush (caused the "overlapping act()" warnings).

## Post-phase corrections (2026-10-10)

A browser smoke run of the web build found three defects that the Jest suites could not see, because Jest has no platform file extensions:

- **Platform self-import.** `notifications.web.ts` / `.native.ts`, `receiptPick.*` and `drive/client.*` imported values from their neutral sibling (`./notifications`, `./receiptPick`, `./client`), which Metro resolves back to the platform file itself. The web app crashed on load (`setNotificationsFactory is not a function`) and `DRIVE_SCOPE`/`DriveError`/`ReceiptPickError` would have been undefined. The shared contracts now live in `notificationsCore.ts`, `receiptPickCore.ts` and `drive/clientCore.ts`, and `scripts/check-boundaries.mjs` fails on any platform file that imports a value from its own neutral sibling.
- **Missing peer dependency.** `react-native-gifted-charts` needs `expo-linear-gradient`; Reports crashed on load. Installed.
- The smoke run covered only the signed-out web landing page (Google sign-in cannot be automated). Signed-in screens on web and everything on Android are still unverified in a browser or on a device.
